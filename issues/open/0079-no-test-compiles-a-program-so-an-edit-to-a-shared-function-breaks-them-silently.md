# 0079 — no test compiles a program, so an edit to a shared function breaks them silently

- **Status:** open
- **Claimed by:** (nobody yet — add yourself before working it)
- **Reported by:** agent-b
- **Date:** 2026-08-05
- **Kind:** diagnostic
- **Symptom:** compile error

`MAP.md` counts 30 command-line programs. The suite compiles the ones a test drives — `packages/box`
and `packages/sh` build theirs per case — and **none** of the rest. `packages/tor` alone has five
`main` entry points and no test mentions any of them:

| program | test references |
| --- | --- |
| `src/app.wac` | 0 |
| `src/socks.wac` | 0 |
| `src/hsfetch.wac` | 0 |
| `src/hsconnect.wac` | 0 |
| `src/relayd.wac` | 0 |

So a program can stop compiling and `deno task test` stays green. The failure surfaces whenever
somebody next tries to run it, with no indication of which change broke it.

## Reproduction

Break any program's compile without touching a library a test imports — deleting a function it alone
calls, or removing an import it alone needs:

```
deno task test                                       # green
deno task app:build packages/tor/src/relayd.wac -o /tmp/x.ts --allow-read
                                                     # error
```

Found by consolidating `rsaFingerprint` out of `relayd.wac` and into `src/routerdesc.wac`. The tor
package's 169 tests passed with the edit in place, and the only reason the program was known to still
build is that it was built by hand afterwards.

## What would settle it

A test that builds every `main` in the repo and asserts nothing more than that it built. It is not a
behavioural test and does not need to be: a compile is the assertion. Discovering the entry points is
already solved — `MAP.md` is generated by walking them, so `tools/map.ts` knows where they are.

The cost is the thing to check before committing to it. `app:build` on `relayd.wac` is not free, and
30 of them in series could be a noticeable fraction of the suite. Options, cheapest first: typecheck
only rather than emit, run it as a separate task the push gate calls rather than inside
`deno task test`, or build only programs whose imports changed.
